// CASE STUDY 01

ECG & Clinical Patient Risk Prediction Pipeline

Problem

Predict cardiovascular risk using ECG signals combined with clinical electronic health record features. Monolithic hospital databases contained high-frequency raw ECG waveforms and categorical clinical data that were challenging to preprocess and analyze concurrently for real-time risk triage.

Approach & Core Architecture

Developed a multimodal machine learning classifier that digests patient clinical metadata and raw ECG waveforms concurrently:

MULTIMODAL ML PIPELINE SCHEMA Raw ECG Signal ➔ 1D-CNN Feature Extraction ➔ Concatenation with EHR Patient Metadata ➔ XGBoost Classifier ➔ Patient Risk Score (FastAPI)

Technical Decisions

PyTorch was chosen for raw tensor operations on high-frequency ECG wave vectors, while scikit-learn handled categorical clinical features preprocessing. SHAP (SHapley Additive exPlanations) values were integrated to render model results explainable for clinicians.

Conversion-Engineered E-Commerce Rebuild

The Challenge

The client was running a legacy WooCommerce monolithic store with slow page speeds (5.8s mobile LCP) causing high cart drop-offs. The goal was to retain the existing WordPress backend database but completely compile a static frontend to maximize page speed and conversion parameters.

Approach & Core Web Vitals

Decoupled the architecture into a headless structure. Built a static frontend using Next.js, serving page assets from global edge networks, and querying product details via the WordPress GraphQL API:

HEADLESS E-COMMERCE ARCHITECTURE Monolith WP Backend ➔ WPGraphQL Plugin ➔ Next.js ISR Static Generator ➔ Edge Network (Vercel CDN) ➔ Fast Client Delivery

Conversion Rate Optimization

Redesigned the checkout page into a streamlined single-step process. Page loads dropped below 1.2 seconds, resulting in direct conversion gains and improved search rankings.

RAG-Powered Intelligent Lead Generation Agent

The Challenge

The client had high bounce rates on cold ad traffic because of slow customer service response times. They needed an intelligent automation system capable of answering complex buyer questions using custom documents, qualifying leads, and syncing customer profiles automatically.

Core Architecture

Built a RAG (Retrieval-Augmented Generation) pipeline integrating vector database indexes with an LLM chat agent interface:

RAG WORKFLOW FLOWCHART Website Visitor ➔ Chatbot Interface ➔ LangChain Query ↓ Vector DB Query (Cosine similarity) ↓ Knowledge Retrieve ➔ Context ➔ OpenAI LLM ↓ Response / Qualify ↓ Slack Alert / CRM Sync

Lead Qualification Workflow

The chatbot parses user questions, retrieves vector segments, and uses structured schema parameters to determine budget fit. High-value qualified leads are instantly synced to HubSpot and Slack.

// CASE STUDY 04

BuyWise 2.0 — AI-Powered Purchase Intelligence SaaS

The Challenge

Consumers struggle with fake reviews, sponsored recommendations, and choice paralysis. Gathering authentic, telemetry-backed purchase signals requires crawling hours of Reddit threads, price history graphs, and technical specifications manually.

System Architecture

Designed a decoupled serverless architecture querying real-time telemetry datasets and parsing sentiment through deep language models:

SYSTEM ARCHITECTURE Browser Client [Next.js 15 App] │ ▼ (REST API Requests) FastAPI Backend API ─── [JWT Guards Authentication] │ ├─► [Key-Value Cache] ─── Upstash Serverless Redis │ ├─► [Relational DB] ──── Neon Serverless Postgres │ ├─► [AI Analysis] ────── OpenAI / Google Gemini API │ └─► [Product Data] ───── Telemetry Product Scraper

Telemetry-Driven Valuation

By analyzing forum discussions, price fluctuations, and direct customer reviews in real-time, BuyWise parses product telemetry indicators into definitive, actionable metrics: Buy Score, Regret Score, and Community Trust Ratings.

Repository Monorepo Layout

The codebase is organized as a production-grade monorepo to separate frontend client concerns from backend services and database migration layers:

CODEBASE DIRECTORY TREE buywise-v2/ ├── apps/ │ ├── web/ # Next.js 15 Frontend (Vite/TypeScript, Tailwind, framer-motion) │ └── api/ # FastAPI Backend Service (SQLAlchemy, Uvicorn, OpenAI/Gemini) ├── packages/ │ └── database/ # Database migrations and configuration schemas ├── .gitignore # Root file mapping ignored folders (node_modules, .venv, .next) ├── README.md # Project developer documentation └── docker-compose.yml # Local services configuration file (Web, API, Postgres, Redis)
